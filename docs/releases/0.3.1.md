# Retrofetch v0.3.1

A backward-compatible startup and installation reliability update. Animation
selection, Fastfetch output, asset quality, and opt-in shell integration remain
unchanged. This release contains code only, not animation collections.

## Improvements

- Stream native dependency verification with bounded memory and reuse one
  verified index/catalog snapshot per invocation.
- Keep supported native playback accelerated across compatible terminal resizing.
- Bind native profile v3, runtime capabilities v2, and layout state v3 to complete
  executable content identities instead of incidental inode/timestamp metadata.
  PATH changes remain safe only when the first Fastfetch renderer still resolves
  to the same canonical executable and content. Invalid current profiles never
  silently downgrade to legacy readers.
- Generate managed Python entrypoints with a validated absolute Python 3.11+
  interpreter, including stable system symlink entries.
- Document optional Omarchy/Kitty launch integration and rollback; installation
  never enables shell startup or changes desktop configuration automatically.

## Upgrade

**Upgrade guidance correction:** the installer prepares a fresh library; it is
not a code-only updater. Reusing cached or local source avoids downloads, not
reimport or normalization. See the [upgrade limitations](../installation.md#upgrading-an-existing-installation)
before changing an existing installation. An installed runtime already matching
this release does not need reinstalling solely because the release was published.

This correction supersedes the original no-reimport claim. Published v0.3.1
artifacts are unchanged; their bundled documentation predates this correction.
Python-only installations remain supported. If native acceleration is desired,
rebuild and explicitly activate the frontend, then run in the target Kitty:

```sh
retrofetch --refresh-runtime
retrofetch --refresh-native
```

Native refresh can reuse saved calibration only when its identities still prove
compatibility; refresh does not rewrite or migrate `layout.json`. Otherwise
explicitly recalibrate using the previous layout mode;
see [native setup](../rendering.md#optional-v3native-acceleration). Startup does
not prepare assets, migrate state, or probe dependencies. Preserve rollback
files until the upgraded installation passes your normal visual checks.

## Distribution and rights

The wheel remains Python-only; the source distribution includes native C build
inputs. Verify downloads against `SHA256SUMS`. Third-party animation notices and
restrictions remain applicable; the repository's MIT license does not license
those assets, and this release does not redistribute them.
